# 对象存储（S3）操作手册

本分支（`mirage-s3`）把**上传字节、知识、派生表缓存**都放在对象存储里，多副本部署不需要共享盘。
决策记录：[ADR-0016](./adr/0016-spaces-in-object-storage.md)（知识）、
[ADR-0018](./adr/0018-uploads-and-reads-through-mirage.md)（上传与读路径）。

> 另一条产品线 `local-spacebackend` 是"Postgres + 本地盘"，上传落 `data/uploads/`、
> 知识只读 `knowledge/`、S3 只用于手动推知识；本文不适用于那条分支。

## 0. 什么进 S3

| 内容 | 前缀 | 谁写 | 谁读 |
|---|---|---|---|
| 会话上传的字节（xlsx / md / 其他） | `uploads/<owner>/<thread_id>/<文件名>` | `custom/service/uploads.py` → `shared/session/blobs.py`（同名覆盖，先备份到 `.bak-<uuid>` 再换） | `okf.backend: s3fs` 时经 Mirage 挂到 `/uploads` |
| 空间知识 | `okf/<space>/…` | `scripts/okf_push_s3.py`（`s3` 模式也可手推） | `s3` 读本地镜像；`s3fs` 由 Mirage 直读 |
| 表的派生 Parquet | `<xlsx.cache_prefix>/<sha256>/h<header>/<sheet>.parquet` + `manifest.json` | `graphs/tools/xlsx/duck.py`（`xlsx.cache_mode: s3`） | 同实例或别的实例直读 `s3://` |
| 历史前缀（已废） | `sessions/<摘要>/<thread>/…` | 旧版上传入口 | 没人读；可清 |

## 1. 起对象存储

仓库根有 `compose.yaml`（Redis + SeaweedFS，Postgres 被注释掉），一键起：

```bash
MSYS_NO_PATHCONV=1 docker compose up -d
```

端口可用 `REDIS_PORT` / `SEAWEEDFS_S3_PORT` / `SEAWEEDFS_MASTER_PORT` / `SEAWEEDFS_FILER_UI_PORT` 覆盖，
默认 S3 网关在 `http://127.0.0.1:8333`。

## 2. 配置

`config.yaml`：

| YAML 键 | 默认 | 说明 |
|---|---|---|
| `s3.endpoint` | 空（空 = 未启用） | 网关地址，如 `http://127.0.0.1:8333`；留空时上传返回 503 |
| `s3.bucket` | `aegra-blobs` | 桶名，启动时自动创建（幂等） |
| `s3.region` | `us-east-1` | 填什么都行（SeaweedFS 不校验） |
| `okf.backend` | `local` | `local` 读本地 `knowledge/`；`s3` 读 S3 镜像；`s3fs` 走 Mirage（**上传只在 s3fs 下可见**） |
| `mirage.redis_url` | `redis://127.0.0.1:6379/0` | Mirage 的缓存/索引；空 = 进程内 |
| `xlsx.cache_mode` | `local` | `s3` = 派生 Parquet 写对象存储并直读，多实例无需共享盘 |

`.env`（只有凭证）：

| 变量 | 默认 | 作用 |
|---|---|---|
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | `dev` / `dev` | 凭证（SeaweedFS 未配 IAM 时任意值） |

> boto3 必须用 path-style：给了 `endpoint_url` 之后它仍默认 virtual-host，`aegra-blobs.127.0.0.1:8333`
> 解析不了。`shared/session/blobs.py` 已写死 `Config(s3={"addressing_style": "path"})`，
> 自己写脚本时别忘。Mirage 的 S3VFS 也统一用 path style。

## 3. 三种形态

| 形态 | `okf.backend` | `s3.endpoint` | 知识从哪读 | 上传文件 agent 能否看见 | 适合 |
|---|---|---|---|---|---|
| 纯磁盘 | `local` | 可留空 | 本地 `knowledge/` | ❌（上传本身仍进 S3，但没有读路径） | 写代码、跑单测 |
| 知识镜像 | `s3` | 必填 | S3 `okf/` 的本地镜像 | ❌ | 多副本只读知识 |
| 全对象存储 | `s3fs` | 必填 | Mirage 直读 S3 | ✅ 挂到 `/uploads` | 生产、多副本 |

## 4. 脚本

```bash
PYTHONPATH=. .venv/Scripts/python.exe scripts/okf_push_s3.py   --dry-run   # 知识推上去
PYTHONPATH=. .venv/Scripts/python.exe scripts/okf_pull_s3.py              # s3 模式：拉镜像
PYTHONPATH=. .venv/Scripts/python.exe scripts/e2e_uploads_mirage.py       # 上传→Mirage 的端到端
PYTHONPATH=. .venv/Scripts/python.exe scripts/reap_upload_orphans.py --older-than-hours 24   # 孤儿字节（默认 dry-run，加 --apply）
PYTHONPATH=. .venv/Scripts/python.exe scripts/reap_multipart.py           # 中断的分片上传 + tmp/
```

## 5. 排错

| 现象 | 原因 |
|---|---|
| 上传返回 `503 上传存储暂不可用` | `s3.endpoint` 为空，或网关不可达 |
| `AccessDenied` / `403` | `.env` 的 key 与实际网关不一致（SeaweedFS 未配 IAM 时任意值都能过） |
| `ls /uploads` 看不到刚传的文件 | `okf.backend` 不是 `s3fs`；只有该模式挂载上传目录 |
| 表查询报 `PermissionException` | `xlsx.cache_mode: s3` 但 `enable_external_access` 被关掉了（不该发生；检查配置来源覆盖） |
| 知识改了但读到旧的 | `s3` 模式下要重跑 `okf_pull_s3.py`（或调 `okf.mirror_ttl_seconds`） |

## 6. 清理

- 删会话：PG 台账靠 `ON DELETE CASCADE` 删行；对象存储里的字节由
  `scripts/reap_upload_orphans.py` 按"前缀不在台账里"清理（默认 dry-run）。
- 中断的分片与 `tmp/`：`scripts/reap_multipart.py`（默认 24h）。
- 手工前缀操作：`blobs.delete_prefix("uploads/<owner>/<thread>/")`，幂等。
