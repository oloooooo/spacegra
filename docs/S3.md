# 对象存储（S3）操作手册

管两件事：**空间知识怎么进 S3**、**所有与对象存储有关的配置在哪里改**。
决策记录见 [adr/0016](./adr/0016-spaces-in-object-storage.md)（空间知识）。

> **2026-11：上传能力已按 ADR-0018 重建**，介质与读路径都可配（`uploads.store` + `okf.backend`，
> 见 §0.1 与 [adr/0018](./adr/0018-uploads-and-reads-through-mirage.md) §9）。
> 下文 §2.1「生产」、§3.2「会话大表」、§4 的 `sessions/` 前缀、§5「上限」、§8 的删会话清理
> 仍属**历史/运维存量**（老对象可能需要清理与对账）。当前代码只往 `okf/`、`uploads/`、
> `xlsx-derived/` 三个前缀写。

## 0. 什么进 S3、什么不进

| 内容 | 存哪 | 生命周期 |
|---|---|---|
| 会话文件里的 **md / xlsx** | `uploads.store` 决定：`s3` → `uploads/<owner>/<thread>/…`；`fs` → 本机 `data/uploads/<owner>/<thread>/…` | 删会话即删（对象/文件由 `scripts/reap_upload_orphans.py` 收） |
| 表格派生 Parquet（由 xlsx 解析） | `xlsx.cache_mode` 决定：`s3` → `xlsx-derived/<sha256>/h<header>/…` 且本机留一份；`local` → 只有本机 | 可丢，删了下次重解析 |
| 空间知识（`knowledge/`） | S3 `okf/…`（`okf.backend: s3` 时读本地镜像，`s3fs` 时 Mirage 直读） | 随空间 |

### 0.1 三种部署形态

| `okf.backend` | `uploads.store` | 需要对象存储 | 适合 |
|---|---|---|---|
| `local` | `fs` | 不需要 | 单机 / demo / 评测机（默认） |
| `s3` | `s3` | 需要 | 旧形态：知识拉本地镜像，上传走对象存储 |
| `s3fs` | `s3`（强制） | 需要 | 多实例集群：Mirage 直读对象存储 |

`uploads.store: auto`（默认）按 `s3.endpoint` 是否配置自动选。**多实例必须用 `s3`**：
`fs` 下每台机器各存各的盘，会话被调度到另一台就看不见自己的文件。

## 1. 起对象存储

本机/Docker（SeaweedFS，S3 协议）：

仓库根有 `compose.yaml`（Redis + SeaweedFS，Postgres 被注释掉），一键起：

```bash
MSYS_NO_PATHCONV=1 docker compose up -d
```

端口可用 `REDIS_PORT` / `SEAWEEDFS_S3_PORT` / `SEAWEEDFS_MASTER_PORT` / `SEAWEEDFS_FILER_UI_PORT` 覆盖，
改完同步 `config.yaml` 的 `s3.endpoint`。手工起单个容器：

```bash
MSYS_NO_PATHCONV=1 docker run -d --name seaweedfs \
  -p 8333:8333 -p 9333:9333 -p 8888:8888 \
  -v seaweedfs-data:/data \
  chrislusf/seaweedfs server -s3 -dir=/data
```

- **Windows + Git Bash 必须加 `MSYS_NO_PATHCONV=1`**：否则 `-dir=/data` 会被改写成
  `E:/tools/Git/data`，容器起来就退出（`Check Meta Folder … Writable: no such file or directory`）。
- 端口：`8333` = S3 网关，`9333` = master，`8888` = filer 的 UI。
- 没有配 IAM 文件时网关匿名放行，`S3_ACCESS_KEY/S3_SECRET_KEY` 填任意值即可（签名仍会被接收）。
- bucket 由应用自动建（`blobs.ensure_bucket()`，幂等），也可手工 `aws s3 mb`。

## 2. 配置

参数分两处：**非密钥的在仓库根 `config.yaml`**（同名环境变量仍可覆盖），**凭证只走 `.env`**。
改完重启进程，不用发版。逐键说明见 [configuration.md §3.2](./configuration.md)。

`config.yaml`（与对象存储、大表有关的部分）：

| 键 | 默认 | 作用 |
|---|---|---|
| `s3.endpoint` | 空（空 = 未启用） | 网关地址，如 `http://127.0.0.1:8333` |
| `s3.bucket` | `aegra-blobs` | 桶名 |
| `s3.region` | `us-east-1` | 填什么都行（SeaweedFS 不校验） |
| `xlsx.max_blob_mb` | `10` | **单个 xlsx 的 HTTP 上传上限**（其他类型看 `session_files.max_upload_mb`） |
| `xlsx.max_cells` | `2000000` | 结构性硬闸：超过直接拒收，不静默截断 |
| `xlsx.max_xlsx_files_per_session` | `20` | 每个会话能挂几个表（同名覆盖不占名额） |
| `xlsx.max_md_files_per_session` | `10` | 每个会话能挂几个 md（⚠ 当前未被读取：文件个数统一按 `session_files.max_files_per_session` 判） |
| `xlsx.max_blob_mb_per_user` | `2048` | 每用户二进制总量（2 GB） |
| `xlsx.cache_dir` | `.cache/xlsx` | 派生缓存与下载字节的本机目录，**必须在 OKF 根之外** |
| `okf.backend` | `local` | `local` 读 `knowledge`；`s3` 读本地镜像 |
| `okf.dir` | `okf` | 空间根目录名（相对 `graphs/`） |
| `okf.mirror_dir` | `.cache/okf` | `s3` 模式的镜像目录 |
| `okf.mirror_ttl_seconds` | `0` | 镜像多久后重新拉；`0` = 不自动刷新 |

`.env`（只有凭证）：

| 变量 | 默认 | 作用 |
|---|---|---|
| `S3_ACCESS_KEY` / `S3_SECRET_KEY` | `dev` / `dev` | 凭证（SeaweedFS 未配 IAM 时任意值） |
| `SESSION_SCOPE_SECRET` | `dev-session-scope` |⚠ 当前代码已不读（会话作用域随上传移除） |

> boto3 必须用 path-style：给了 `endpoint_url` 之后它仍默认 virtual-host，`aegra-blobs.127.0.0.1:8333`
> 解析不了。代码里已写死 `Config(s3={"addressing_style": "path"})`，自己手写脚本时别忘。

### 2.1 两套部署形态：开发用磁盘、生产用 S3

**关键区别：`okf.backend` 只管“空间知识从哪读”。`s3.endpoint` 管“要不要对象存储”。**
两者独立，所以有三种组合：

| 形态 | `okf.backend` | `s3.endpoint` | 空间知识从哪读 | 上传会话大表 | 适合 |
|---|---|---|---|---|---|
| **纯磁盘**（开发缺省） | `local` | **留空** | `knowledge/` | ❌ 接口 `503` | 写代码、跑单测、不想装 SeaweedFS |
| **混合** | `local` | 填本机网关 | `knowledge/` | ✅ | 只试大表链路 |
| **全 S3**（生产） | `s3` | 填集群网关 | S3 `okf/` 的本地镜像 | ✅ | 多副本部署 |

#### 开发（纯磁盘，不需要 SeaweedFS）

```yaml
# config.yaml
okf:
  backend: local
  dir: knowledge                # 空间根 = knowledge（仓库根，不在代码包里）
s3:
  endpoint: ""                  # 留空 = 对象存储不启用
uploads:
  store: auto                   # auto → 没有 endpoint 就是 fs
  dir: data/uploads             # store=fs 时的落地目录（相对仓库根）
xlsx:
  cache_dir: .cache/xlsx
```

这一档下：

- 空间里的 xlsx（`/空间名/x.xlsx`）**四个工具照常用**：读本地盘 → 首次查询解析成
  Parquet 落 `xlsx.cache_dir` → DuckDB 查。
- 上传落本机 `data/uploads/<owner>/<thread>/`，`/uploads/` 由 `LocalBackend` 只读挂载，
  **不需要 S3 凭证、不需要起网关**。
- 派生缓存默认 `xlsx.cache_mode: local`；即使写了 `s3`，没配对象存储时也会自动退回本地。
- 删会话时台账行 CASCADE；本地字节与无主文件由 `scripts/reap_upload_orphans.py` 按 24h 窗口收。

#### 生产（空间 + 会话文件都在 S3）

```yaml
# config.yaml
okf:
  backend: s3
  mirror_dir: /var/cache/aegra/okf        # 部署时给绝对路径
  mirror_ttl_seconds: 300                 # 0 = 不自动刷新，只靠 pull 脚本
s3:
  endpoint: http://seaweedfs:8333
  bucket: aegra-blobs
xlsx:
  cache_dir: /var/cache/aegra/xlsx        # 同上：给绝对路径
```

```ini
# .env —— 只有凭证
S3_ACCESS_KEY=…
S3_SECRET_KEY=…
# （旧版的 SESSION_SCOPE_SECRET 已废弃：上传重建后没有代码读它）
```

从开发切到生产，按这个顺序做：

```bash
# 1) 把当前空间内容推到 S3（幂等，可反复跑）
PYTHONPATH=. .venv/Scripts/python.exe scripts/okf_push_s3.py --prune
# 2) 改 config.yaml：okf.backend: s3 + 上面那组 s3.* 参数
# 3) 每个副本拉一次镜像（或直接启动，镜像缺失时会自动拉）
PYTHONPATH=. .venv/Scripts/python.exe scripts/okf_pull_s3.py
# 4) 自检
PYTHONPATH=. .venv/Scripts/python.exe -m pytest tests/unit/test_okf_mirror.py tests/unit/test_blobs.py -q
```

注意：

- `config.yaml` 里 `s3.endpoint` 默认留空（= 不启用）。要試本机网关就填
  `http://127.0.0.1:8333`；**不起网关就保持空**，否则上传会变成 `503` 而不是“未启用”的清晰降级。
- `xlsx.cache_dir` / `okf.mirror_dir` 默认是相对 CWD 的 `.cache/…`，生产要给绝对路径，
  且**不能落在 OKF 根下**（根散文件对所有登录用户只读共享）。
- `s3` 模式下空间内容改了，必须 `okf_pull_s3.py`（或设 `okf.mirror_ttl_seconds` 让它自己过期），
  否则各副本读到旧内容。

## 3. 上传本地文件

### 3.1 空间知识（`knowledge/` → `okf/` 前缀）

```bash
# 看要传什么
PYTHONPATH=. .venv/Scripts/python.exe scripts/okf_push_s3.py --dry-run

# 传（幂等：对象已存在且大小相同就跳过）
PYTHONPATH=. .venv/Scripts/python.exe scripts/okf_push_s3.py

# 顺带删掉 S3 上本地已没有的对象
PYTHONPATH=. .venv/Scripts/python.exe scripts/okf_push_s3.py --prune
```

让服务读 S3 里的空间知识：

```yaml
# config.yaml
okf:
  backend: s3
  mirror_dir: .cache/okf
  mirror_ttl_seconds: 0     # 0 = 只在镜像缺失时拉；改了空间内容重跑下面的 pull
```

```bash
# 手动刷新镜像（多个副本都跑一次；或设 TTL 让它自己过期重拉）
PYTHONPATH=. .venv/Scripts/python.exe scripts/okf_pull_s3.py
```

> 为什么是镜像而不是"直接读 S3"：见 ADR-0016 的「决定变更」。一句话——`BackendProtocol`
> 有 14 个方法（ls/read/grep/glob/…），在对象存储上重写一遍的正确性风险远大于收益，
> 而镜像让 8 个 fs 工具走的还是同一份已测实现。

### 3.2 会话文件（xlsx / md → `uploads/` 前缀）

走 HTTP：`POST /custom/uploads`（`multipart/form-data`，字段 `thread_id` + `file`）。
落点由 `uploads.store` 决定：`s3` → 对象存储 `uploads/<owner>/<thread>/<文件名>`；
`fs` → 本机 `<uploads.dir>/<owner>/<thread>/<文件名>`（默认就是这个，不需要 S3）。
文件名里的空间名只决定**派给哪个子 agent**，不决定存哪（ADR-0018）。

```bash
# 文件名形如 <空间名>_<表名>.xlsx；空间不在你的授权内就派给通用 xlsx 子 agent
curl -X POST http://127.0.0.1:2026/custom/uploads \
  -H "Authorization: Bearer $TOKEN" \
  -F "thread_id=$THREAD_ID" \
  -F "file=@./报价表.xlsx;filename=cbam-reporting_报价表.xlsx"
```

成功返回 `201`：

```json
{"name": "cbam-reporting_报价表.xlsx", "size": 4956, "sha256": "…",
 "target_agent": "cbam-reporting", "virtual_path": "/uploads/cbam-reporting_报价表.xlsx"}
```

错误码：

| 码 | 情况 |
|---|---|
| `404` / `403` | 会话不存在 / 不是你的 |
| `413` | 超 `xlsx.max_blob_mb`（表格）或 `session_files.max_upload_mb`（其他） |
| `409` | 超 `session_files.max_files_per_session` 个文件 |
| `422` | 文件名非法（含 `/` `\` NUL、`.`、`..`、>200 字符） |
| `503` | 上传存储不可用（对象存储挂了 / bucket 不可写） |

要点：

- **解析发生在第一次查询**，不在上传时：上传只流式写字节。首次 `xlsx_*` 工具调用把每个
  sheet 转成 Parquet（`xlsx.cache_dir/derived/<sha256>/h<header>/`，`cache_mode=s3` 时同时
  写 `xlsx-derived/`），之后所有查询都走 DuckDB `read_parquet`。
- 同名重传 = 覆盖（台账 upsert，`<owner>/<thread>/<name>` 只一份字节）。
- 子 agent 只有在**同一条会话**里才读得到：读侧靠目录键（`<owner>/<thread>`）与 Mirage
  的 profile 白名单（`s3fs` 模式）或 `LocalBackend` 的 root（`fs` 模式），不再有 session_scope 凭证。
- 删除入口是删会话（`DELETE /threads/{id}`）：台账行随线程 CASCADE，字节由
  `scripts/reap_upload_orphans.py --apply` 收（24h 窗口，避开在途上传）。

### 3.3 运维直连（脚本/手工）

```python
import boto3
from botocore.config import Config

s3 = boto3.client("s3", endpoint_url="http://127.0.0.1:8333",
                  aws_access_key_id="dev", aws_secret_access_key="dev",
                  region_name="us-east-1",
                  config=Config(s3={"addressing_style": "path"}))
s3.upload_file("本地路径.xlsx", "aegra-blobs", "tmp/manual/x.xlsx")
```

或者 `aws --endpoint-url http://127.0.0.1:8333 s3 ls s3://aegra-blobs/okf/`。

> 手工放进 `uploads/…` 前缀的**对象不会被任何工具读到**——`session_object` 表里没有对应行，
> 工具查的是那一行。要造会话文件请走 3.2 的接口。

## 4. Key 布局

```
uploads/<owner>/<thread>/<name>                                     上传字节（uploads.store=s3）
<uploads.dir>/<owner>/<thread>/<name>                               上传字节（uploads.store=fs）
xlsx-derived/<sha256>/h<header>/<sheet>.parquet                     表格派生缓存（xlsx.cache_mode=s3）
okf/<space>/...                                                     空间知识
tmp/{uuid4}/{name}                                                  分片上传中转，7 天生命周期兜底
```

- `owner` 是上传者 identity **原样**（不摘要）：它同时是 Mirage `/uploads` mount 的
  `key_prefix`，两处必须逐字节一致；空间知识的 `okf/` 不带 owner，隔离靠 profile 白名单。
- `<sha256>` 是**上传字节的哈希 + 表头行号**（`h<header>`）：同一份表在任何实例上解析结果
  相同，可以共享；内容变了自然换目录，不需要失效逻辑。
- 旧的 `sessions/{h(identity)}/{thread_id}/…` 与 `.sqlite` 索引已废弃（2026-11 重构），
  存量对象可以直接删。

## 5. 上限是怎么判的

上传时按这个顺序，每步都比下一步便宜：

1. 会话归属（`404` / `403`）；
2. `Content-Length` / `file.size` 超上限 → `413`，一个字节都不读（表格看 `xlsx.max_blob_mb`，
   其余看 `session_files.max_upload_mb`）；
3. 同会话文件数超 `session_files.max_files_per_session`（同名覆盖不计数）→ `409`；
4. 流式读 64 KB：边计数边算 sha256，超线立刻中止（`fs` 写同目录临时文件后 `os.replace`；
   `s3` 走分片上传，能 abort）；
5. 文件名规则 → `422`；
6. 写序：**先写字节、再 upsert 台账**，台账写失败则删掉刚写的字节。
   崩在中间只会留一个没有行指向的孤儿文件，不会出现“行说 A、字节是 B”。

`xlsx.max_cells` 不是上传时判的——上传只流式写字节，服务端不落本地副本，看不到行列。它**第一次调工具时**判：
`openpyxl read_only` 探行列数（实测 27 ms），超了直接报错，**不建索引、不静默截断**。
所以一张“能上传但处理不了”的表不会先跑几十秒再撞超时。

## 7. 排错

| 现象 | 原因 / 处理 |
|---|---|
| 容器起来立刻退出，日志 `Check Meta Folder (-mdir="E:/…")` | Git Bash 改了 `-dir`，加 `MSYS_NO_PATHCONV=1` |
| `botocore ... ConnectTimeout` / `EndpointConnectionError` | `s3.endpoint` 写错或网关没起；先 `curl http://127.0.0.1:8333` |
| `InvalidRequest` / DNS 解析失败里带 `bucket.127.0.0.1` | 没配 path-style（见 §2 末尾） |
| 上传 `503` | 服务进程里 `s3.endpoint` 为空且 `uploads.store` 被显式写成 `s3`；或者对象存储真的挂了。单机优先用 `uploads.store: fs` |
| 分片对象的 `ETag` 不是文件 md5 | 正常：只有单次 PUT 的 ETag 才是 md5 |
| 未完成分片一直占空间 | `blobs.abort_stale_multiparts(86400)`（`upload_fileobj` 那条路拿不到 upload_id，我们已改成自己管分片） |
| 空间文件改了但服务读到旧的 | `okf.backend: s3` 下要重跑 `scripts/okf_pull_s3.py`（或调 `okf.mirror_ttl_seconds`） |
| 索引像是旧的 | 本机派 Parquet 缓存 `xlsx.cache_dir` 可整目录删；内容寻址、删了只是下次多解析一遍 |

## 8. 清理与容量

- **删会话**（唯一正常的删除入口）：台账行随线程 CASCADE（迁移 `b8c9d0e1f2a3`），
  字节不跟着消失——对象存储里的用 `scripts/reap_upload_orphans.py --apply` 按
  “台账里已没这个会话且够老” 收，本地的同一脚本按文件 mtime 收。
- **手工清前缀**：`blobs.delete_prefix("uploads/<owner>/<thread>/")`，幂等。
- **上传垃圾（必须定期跑）**：`scripts/reap_multipart.py` 清两样东西——超过 `--older-than-hours`
  （默认 24h）的 `tmp/` 中间对象，以及超时未完成的分片。两者对象存储都不会自动回收：
  上传写序是 `tmp/` → copy 到正式 key → PG 事务 → 删 `tmp/`，中途崩就留下；分片是
  `upload_fileobj` 拿不到 `upload_id` 的后果。**空跑先看数**：
  `PYTHONPATH=. python scripts/reap_multipart.py --dry-run`。
  挂 cron / 任务计划每几小时跑一次；不跑脚本就用对象的生命周期规则兜底
  （`tmp/` 前缀过期删除 + `AbortIncompleteMultipartUpload` 自动 abort）。
  这是**运维脚本，不是 crons API**——aegra 的定时任务只触发图 run。
- **对账**：PG 的 `sum(size_bytes)` 不含索引与被覆盖的旧对象（历史遗留），物理用量可能更大。
  要精确就把 `spaces/`、`sessions/` 前缀逐个 `list_objects_v2` 累加。
